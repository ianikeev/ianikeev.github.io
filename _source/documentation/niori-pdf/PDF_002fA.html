16 PDF/A-2b archival output ¶

PDF/A (ISO 19005) is the archival flavor of PDF: everything needed to render the file is embedded, so the document displays identically decades from now. niori-pdf implements the pragmatic flavor, PDF/A-2b (level B, based on PDF 1.7): transparency, JPEG images and URI/GoTo link actions stay legal, and no structure tagging is required. PDF/A-1 is deliberately not supported (it forbids transparency), nor is PDF/A-3 (it adds embedded files, which archival reports rarely need).

Function: niori-pdf-pdfa-enable doc &optional level ¶

Enable PDF/A-2b output for doc. level must be 2 (the default). Registers the metadata/output-intent catalog extension and the annotation save hook; niori-pdf-save then writes a %PDF-1.7 header and an /ID trailer. Returns doc. In flow documents, simply pass :pdfa t to niori-pdf-with-flow-document instead of calling this function.

What changes when PDF/A is enabled:

  • /Metadata — the document catalog gets an uncompressed XMP packet with pdfaid:part/pdfaid:conformance and the dublin-core properties (title, creator, subject, keywords), mirroring the Info dictionary byte for byte as ISO 19005-2 6.6.2 requires.
  • /OutputIntents — a GTS_PDFA1 OutputIntent with an embedded ICC profile as /DestOutputProfile, so DeviceRGB and DeviceGray colors are valid. The profile is generated in pure Elisp: a minimal, deterministic ICC v2 matrix/TRC profile (sRGB primaries, gamma 2.2 TRCs, D50 media white point; about 600 bytes). It is a structurally valid ICC profile — verified against lcms2 — but it describes a gamma-2.2 approximation of sRGB rather than the exact sRGB parametric curve.
  • /ID — the trailer carries an MD5-based /ID array (also written for plain documents; harmless and useful).
  • Link annotations get the Print flag (/F 4, ISO 19005-2 6.8).
  • Fonts — every font must be embedded (ISO 19005 forbids unembedded fonts, without exception for Symbol/ZapfDingbats). The base-14 names are therefore rejected unless niori-pdf-pdfa-base14-substitutions maps them to a font file; .ttf/.otf/.ttc/.pfb/.pfa fonts embed as usual.
  • Color — DeviceCMYK is rejected (the built-in OutputIntent is sRGB); use RGB or grayscale.
User Option: niori-pdf-pdfa-base14-substitutions ¶

Alist mapping base-14 font names to embedded font specs used in PDF/A documents, e.g.: 

(setq niori-pdf-pdfa-base14-substitutions
      '(("Helvetica" . "/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf")
        ("Helvetica-Bold"
         . "/usr/share/fonts/truetype/dejavu/DejaVuSans-Bold.ttf")
        ("Symbol" . "/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf")))

The replacement can be any font spec accepted by niori-pdf-set-font. Since Symbol/ZapfDingbats text is drawn from Unicode strings through the font’s own encoding map, mapping them to a TrueType font with the right codepoints (DejaVu Sans covers the dingbats and Greek used in the examples) preserves the glyph appearance without the unembedded base-14 fonts.
