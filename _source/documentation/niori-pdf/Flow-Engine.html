9 The Flow Engine ¶

The flow engine is the Elisp counterpart of cl-typesetting: you declare blocks, it wraps lines, breaks pages and keeps headings with their content. All block functions operate on the dynamic flow context established by niori-pdf-with-flow-document.

Macro: niori-pdf-with-flow-document (props) body… ¶

Establish a flow context. props: :width :height :margins (list (left top right bottom), default (54 56 54 56)) :header-fn :footer-fn (functions of (flow page-number)) :default-font :default-size :language :hyphenate :vjustify :pdfa (enable PDF/A-2b archival output, see PDF/A-2b archival output) and the document info keys.

Function: niori-pdf-flow-generate builder ¶

Run builder (a thunk that calls the block functions) and return the document. The builder is re-run until the layout is stable: the table-of-contents entries, the reference points recorded with niori-pdf-flow-mark-ref-point and the per-page footnote block heights must stop changing between passes (at most six passes), so the TOC, every cross-reference and the footnotes show correct results.

Function: niori-pdf-flow-save doc file ¶

Write the document (same as niori-pdf-save).

Blocks ¶

Function: niori-pdf-flow-paragraph content &rest keys ¶

content is a string or a list of runs; a run is a string or a (TEXT &key font size color superscript subscript underline strike background) form. :superscript/:subscript set the run at 66% of the base size with the appropriate baseline offset, :underline and :strike draw rules under and through the run, and :background fills an RGB rectangle behind it. Paragraph keys: :align left|center|right|justified, :font :size :leading :color :indent :space-before :space-after. Paragraphs are broken with the Knuth-Plass algorithm over the box/glue/penalty model (three TeX-style passes with pretolerance, tolerance and emergency stretch); lines are set with TJ adjustments. With :align justified the last line keeps its alignment. Hyphenation uses TeX patterns via :hyphenate (default t) and :language (american british german french spanish italian portuguese esperanto ukrainian russian; the Portuguese set covers both European and Brazilian Portuguese). Words that contain an explicit hyphen (compound identifiers such as niori-pdf-curve-to) follow the TeX rule: pattern hyphenation is disabled for them and the break opportunities sit after their existing hyphens, with no second hyphen glyph at the line end.

Function: niori-pdf-flow-heading text &key level font size color space-before space-after toc ¶

Styled heading (levels 1..4 with default styles). Headings reserve space for the following block (keep-with-next) and, unless toc is nil, record an entry for the table of contents.

Function: niori-pdf-flow-table spec ¶

Grid table. spec keys: :cols (widths or :auto), :header, :rows, :padding, :header-bg :header-fg, :borders (RGB list or nil), :font :size :align. A cell is a string or a plist (:text :font :size :color :align :background :colspan :rowspan :valign): :colspan and :rowspan span the grid (:valign is top, center or bottom inside the spanned rectangle). A row is a list of cells — or a plist (:cells :keep-with-next :background): :keep-with-next moves the row to the next page together with its successor and :background fills the whole row. Cell text wraps; row heights are computed from the wrapped cells (a rowspan cell contributes to the sum of its covered rows); tables split across pages, repeat the header row, and never break inside a span. Columns whose minimum word width exceeds their width are widened, funded by the surplus columns. :space-after adds vertical space between the closing rule and the next block (default 0).

Function: niori-pdf-flow-image path &key width max-height align caption ¶

Image block, scaled to width (fitting max-height), with an optional centered caption.

Function: niori-pdf-flow-box builder &key background border padding width align ¶

Draw a box around the blocks produced by builder; useful for KPI cards and callouts.

Function: niori-pdf-flow-columns builders &key widths gap row-height ¶

Lay out several builders side by side (KPI rows); the row is as tall as the tallest column.

Function: niori-pdf-flow-rule &key thickness color indent space-before space-after ¶

Horizontal rule.

Function: niori-pdf-flow-spacer h ¶
Function: niori-pdf-flow-vglue &optional stretch ¶
Function: niori-pdf-flow-vfill ¶
Function: niori-pdf-flow-page-break ¶

Fixed vertical space; stretchable vertical glue (like TeX’s \vskip with stretch units of stretch); infinitely stretchable glue (\vfill); forced page break. When a page ends, the leftover space above the bottom margin is distributed over its vertical glues proportionally to their stretch — blocks after a glue are shifted down with a PDF cm transform, so text, rules and images all move together. Give the document :vjustify t to treat every block boundary as a weak glue (vertical justification), as in cl-typesetting’s filled vboxes.

Function: niori-pdf-flow-itemize items &key bullet bullet-color indent gap font size color align space-between space-before space-after hyphenate language ¶

Bulleted list. items are strings or run lists; each item is a paragraph with a hanging indent and the bullet drawn left of its first line.

Function: niori-pdf-flow-enumerate items &key start format marker-color indent gap font size color align space-between space-before space-after hyphenate language ¶

Numbered list; markers are formatted with format (default "%d.") from start (default 1) and right-aligned in a common column.

Function: niori-pdf-flow-float builder &key width side gap ¶

Float the blocks produced by builder (a thunk) to side (left, default, or right), width points wide. Paragraphs and rules on the same page wrap around the float; the flow cursor stays at the float’s top, so content fills the space beside it. Floats do not survive a page break.

Function: niori-pdf-flow-toc ¶

Table of contents. Place it early in the document (typically after a title block, before a niori-pdf-flow-page-break). Entries are collected from the headings; niori-pdf-flow-generate re-runs the builder so page numbers are correct.

Reference points (cross references) ¶

Function: niori-pdf-flow-mark-ref-point id &optional data ¶

Record a reference point id at the current position (with arbitrary data). Collected across the multi-pass layout.

Function: niori-pdf-flow-ref-page-number id &optional default ¶
Function: niori-pdf-flow-ref-data id ¶
Function: niori-pdf-flow-ref id ¶

Page number / data / whole entry of reference point id from the previous pass (nil on the first pass) — use them inside your own content to print “see chapter N”.

Function: niori-pdf-flow-put-ref-page-number id &key font size color align unresolved ¶

Typeset the page number of id, right-aligned by default; on the first pass unresolved (an em dash) is printed instead and the multi-pass loop re-runs the builder until the real number appears.

Footnotes ¶

Function: niori-pdf-flow-footnote text &key marker font size leading color ¶

Register text as a footnote for the current page and return its marker. The note is set in a block at the bottom of the page, below a short LaTeX-style separator rule (niori-pdf-flow-footnote-rule-width of the text measure; color niori-pdf-flow-footnote-rule-color), when the page is flushed. marker defaults to the note’s number on the page (‘1’, ‘2’, …); embed it in the citing paragraph as a superscript run: 

(let ((fn (niori-pdf-flow-footnote "Studio notes.")))
  (niori-pdf-flow-paragraph
   (list "Text cites a source" (list fn :superscript t) ".") ...))

font, size (default 8), leading (default 1.24) and color style the note text. Pages that carry footnotes are shortened by their note block’s height on the next layout pass of niori-pdf-flow-generate, so the notes always fit between the text and the bottom margin. Register the note adjacent to the paragraph that cites it: a note belongs to the page that is current when niori-pdf-flow-footnote runs.

Page furniture ¶

Two ready-made template functions can be passed as :header-fn/:footer-fn: niori-pdf-flow-page-footer draws a centered ‘- n -’ page number; niori-pdf-flow-page-header draws the document title left and the page number right in the top margin. Custom functions receive the flow context and the page number and may use the ordinary content-level operators.
